# SPR-010 — Governança do Prisma Client + CI

## Objetivo

Fechar `TECH-001` formalizando a política de versionamento de artefatos gerados do Prisma
(`ADR-006`) e implementar um pipeline de Continuous Integration (GitHub Actions) que a aplique
automaticamente.

Decisão de arquitetura: `ADR-006-generated-artifacts-versioning-policy.md`, design completo em
`SPR-010-infra-tooling.md`.

## Contexto

`TECH-001` documentou, desde o Repository Health Check pré-SPR-008, que
`apps/api/generated/prisma/**` está versionado sem decisão arquitetural formal, com risco de
divergência silenciosa em relação a `schema.prisma`. Esse risco foi vivido concretamente em toda
a SPR-009, que também não teve nenhuma automação de validação — todo lint/teste/build/E2E foi
executado manualmente a cada bloco.

## Escopo

- `ADR-006 — Generated Artifacts Versioning Policy`.
- Pipeline de Continuous Integration (GitHub Actions): lint, testes unitários, build, verificação
  de sincronização do Prisma Client, PostgreSQL real, migrations, testes E2E.
- Execução automática em Pull Request contra `main` e em push para `main`.
- Fechamento formal de `TECH-001`.

## Fora de Escopo (explicitamente, nesta sprint)

- `Campaign`, registro público de usuários — sprints futuras (`SPR-011`, `SPR-012`).
- Qualquer trabalho de frontend.
- **CD/deploy automático** — esta sprint implementa Continuous Integration, não Continuous
  Deployment. Nenhum artefato do repositório demonstra decisão prévia sobre deploy automático.
- OAuth, recuperação de senha, 2FA, geração por IA.
- Qualquer código de domínio ou alteração em `Project`.
- Alteração de `engines.node` (permanece `>=18`) e criação de `.nvmrc` — sem evidência
  arquitetural que as exija nesta sprint.
- **Configuração de branch protection no GitHub** — é ação operacional do Arquiteto-Chefe, fora
  do que um patch de código consegue implementar; o workflow desta sprint produz o sinal
  (verde/vermelho), não o bloqueio de merge em si.

do merge, sem permanecer no repositório).

## Dependências

- SPR-009 encerrada (confirmado).
- `docker/docker-compose.yml` como referência de topologia de Postgres para o service container
  da CI.
- `apps/api/test/.env.test` já commitado — nenhum GitHub Secret necessário.

## Riscos

- Sem branch protection configurada após o Bloco B, a CI existe mas não impede merge — risco
  operacional, não de código, fora do escopo deste patch.
- `prisma generate`/`migrate deploy` em CI dependem de rede externa a `binaries.prisma.sh` — sem
  risco elevado, já que runners do GitHub Actions têm acesso irrestrito.

## Estratégia de Validação

Cada bloco: lint, testes unitários e build verdes. Bloco B adicionalmente: pipeline testado tanto
em cenário positivo quanto em cenário negativo controlado (divergência proposital do Prisma
Client), antes de ser considerado pronto para revisão.

## Condição de Encerramento

A sprint só é considerada encerrada quando: `ADR-006` estiver `Accepted`; `TECH-001` estiver
fechada; o workflow de CI estiver mergeado em `main` e comprovadamente detectar tanto o cenário
positivo quanto o negativo; a documentação (`README.md`, `PROJECT_STATUS.md`) estiver consistente
com o que foi de fato implementado (CI, não CI/CD); e o Arquiteto-Chefe aprovar formalmente o
encerramento — mesmo procedimento de `engineering/runbooks/sprint-closure.md`.
