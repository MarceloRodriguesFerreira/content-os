# SPR-009 — Domínio: Projetos

## Objetivo

Inaugurar a camada de domínio do Content-OS com o primeiro agregado de negócio: `Project`.

Decisões de arquitetura: `ADR-008-project-aggregate-strategy.md`,
`ADR-009-resource-ownership-authorization.md`, `ADR-010-rest-api-conventions.md`,
design completo em `SPR-009-projects-domain.md`.

Segue o mesmo padrão de execução incremental por blocos adotado na SPR-008: cada bloco termina
com lint, testes, build, relatório técnico, e aguarda aprovação antes do próximo.

**Diferença deliberada em relação à SPR-008:** na SPR-008, cada bloco adicionava sobre um
`Controller` HTTP que já existia desde uma sprint anterior — havia sempre uma superfície HTTP
para testar via E2E a cada bloco. Aqui, `ProjectsController` só passa a existir no Bloco C — não
há nenhuma rota HTTP para exercitar via E2E antes disso. Por isso, testes E2E completos ficam
concentrados no Bloco C; Blocos A e B são cobertos por testes unitários (Repository, Service,
Guard isolados), o que é suficiente e correto para camadas sem superfície HTTP própria — não é
uma redução de rigor, é a granularidade de teste certa para cada camada.

## Bloco A — Persistência

- [ ] `enum ProjectStatus` e `model Project` no `schema.prisma` (`ADR-008`)
- [ ] Relação inversa `projects Project[]` em `User`
- [ ] Migration
- [ ] `ProjectsRepository` (Repository Pattern — `findById`, `findManyByOwner` com paginação/
  filtro, `create`, `update`, `updateStatus`). Recebe parâmetros primitivos (`{ ownerId, status,
  skip, take }`), não os DTOs HTTP do Bloco C — a camada de persistência não conhece a forma da
  requisição HTTP, mesmo padrão de separação já usado em `UsersRepository`. Isso desacopla o
  Bloco A do Bloco C: o Repository pode ser implementado e testado sem que `ListProjectsQueryDto`
  exista ainda.
- [ ] Testes unitários do `ProjectsRepository`

**Critério de saída:** lint, testes unitários e build verdes. Relatório técnico entregue.
Aguardar aprovação antes do Bloco B.

## Fora de Escopo (explicitamente, nesta sprint)

- Campanha, Conteúdo, Publicação (entidades filhas — sprints futuras)
- Colaboração multi-usuário em projetos (compartilhamento/membros)

- Ordenação customizável na listagem (fixo: `createdAt desc`)
- Painel administrativo de "todos os projetos" (RBAC administrativo já cobre acesso por `:id`,
  mas não uma listagem global)
- Endpoint público de registro de usuários, pipeline de CI/CD, `TECH-001`/`ADR-006` — pendências
  registradas em trilhas próprias, não desta sprint (ver `PROJECT_STATUS.md`)
