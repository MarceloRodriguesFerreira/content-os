# SPR-012 — Domínio: Campaign

## Objetivo

Modelar `Campaign` como primeiro agregado filho de `Project`, evoluindo o domínio de negócio do
Content-OS iniciado na SPR-009. `Campaign` não possui `ownerId` próprio — a posse é derivada
exclusivamente de `Campaign.projectId → Project.ownerId`.

Decisões de arquitetura: `ADR-011-campaign-ownership-authorization.md`.

Segue o mesmo padrão de execução incremental por blocos adotado nas SPR-008 e SPR-009: cada
bloco termina com lint, testes, build, relatório técnico, e aguarda aprovação antes do próximo.

**Mesma diferença estrutural já registrada na SPR-009 em relação à SPR-008:** `CampaignsController`
só passa a existir no Bloco C — não há superfície HTTP para exercitar via E2E antes disso. Testes
E2E completos ficam concentrados no Bloco C; Blocos A e B são cobertos por testes unitários
(Repository, Service, Guard isolados).

**Diferença em relação à SPR-009:** `Campaign` é um recurso de segundo nível (filho de `Project`,
sem `ownerId` próprio), o que exige que a autorização atravesse o recurso pai e valide
consistência entre `:projectId` e `:id` na rota — problema que `ProjectOwnershipGuard` nunca
precisou resolver. Ver `ADR-011` para a análise completa e a decisão de manter
`CampaignOwnershipGuard` como guard específico do módulo (YAGNI, sem abstração compartilhada com
`ProjectOwnershipGuard`).

- [x] Migration

  paginação/filtro de status, `create`, `update`, `updateStatus`). Recebe parâmetros primitivos,

- [x] Testes unitários do `CampaignsRepository`
- [x] Sem `@@unique([projectId, name])` e sem cascata de estado entre `Project` e `Campaign`
  (decisões de domínio registradas)

**Critério de saída:** lint, testes unitários e build verdes. Relatório técnico entregue.
Aprovado (PR #17, commit `c2eaf5f`). Bloco B autorizado.

## Bloco B — Regras de Negócio e Autorização — ✅ Concluído (aprovado pelo Arquiteto-Chefe)

- [x] `CampaignsService` (criação, atualização parcial, `archive` — não-idempotente, `409` em
  transição para o mesmo estado —, listagem delegando paginação/filtro ao repository). Não
  realiza nenhuma verificação de ownership — responsabilidade exclusiva do guard
- [x] `ADR-011-campaign-ownership-authorization.md` — formaliza três decisões: guard específico
  de módulo (sem abstração compartilhada com `ProjectOwnershipGuard`); falhas de ownership de
  `Campaign` retornam sempre `404` (nunca `403` — divergência consciente e localizada em relação
  à `ADR-009`, que permanece integralmente válida para `Project`); e a ordem de validação obrigatória
  em rotas com `:projectId` + `:id` (Campaign → consistência com `:projectId` → Project →
  ownership) para prevenir IDOR
- [x] `CampaignOwnershipGuard` implementando a `ADR-011`
- [x] `CampaignsModule` (registro inicial)
- [x] Testes unitários do `CampaignsService` e do `CampaignOwnershipGuard`

**Critério de saída:** lint, testes unitários e build verdes. Relatório técnico entregue.
Aprovado (PR #18, commit `fb92c6b`). Bloco C autorizado.

## Bloco C — API REST — ✅ Concluído (aprovado pelo Arquiteto-Chefe)

- [x] DTOs (`CreateCampaignDto`, `UpdateCampaignDto`, `ListCampaignsQueryDto`,
  `CampaignResponseDto` — específicos do módulo; `projectId` nunca é campo de body, sempre vem
  da rota, mesmo motivo pelo qual `ownerId` não existe em `CreateProjectDto`)
- [x] `CampaignsController` sob `/v1/projects/:projectId/campaigns`, com
  `@UseGuards(CampaignOwnershipGuard)` declarado explicitamente em toda rota:

  ```
  POST   /v1/projects/:projectId/campaigns
  GET    /v1/projects/:projectId/campaigns
  GET    /v1/projects/:projectId/campaigns/:id
  PATCH  /v1/projects/:projectId/campaigns/:id
  POST   /v1/projects/:projectId/campaigns/:id/archive
  ```

- [x] `CampaignsModule` registrado em `AppModule`
- [x] Swagger (tags, `@ApiProperty`, exemplos, respostas de erro incluindo `404` para os cinco
  cenários de falha de ownership da `ADR-011`)
- [x] Testes E2E completos (fluxo, isolamento entre usuários, acesso administrativo, IDOR —
  campanha real com `:projectId` de outro projeto do próprio usuário —, paginação, validação,
  conflito de estado no `archive`)
- [x] Atualização de `PROJECT_STATUS.md`, `CHANGELOG.md`

**Critério de saída:** lint, testes unitários, build **e E2E** verdes. Relatório técnico
entregue. Aprovado (PR #19, commit `21d154a`) — encerra a SPR-012.

## Fora de Escopo (explicitamente, nesta sprint)

- `Conteúdo`, `Publicação` (entidades filhas de `Campaign` — sprints futuras)
- Restauração de campanha arquivada (`restore` — só existe `archive`; `ARCHIVED` é terminal
  nesta sprint)
- `DELETE` físico de campanha
- `@@unique([projectId, name])` — nomes de campanha não são únicos por projeto
- Cascata de estado entre `Project` e `Campaign` (arquivar/restaurar um `Project` não afeta suas
  `Campaign`s)
- Abstração genérica de `OwnershipGuard` compartilhada entre `Project` e `Campaign` — adiada até
  um terceiro consumidor real (ver "Future Evolution" da `ADR-011`)
- Ordenação customizável na listagem (fixo: `createdAt desc`, mesmo padrão de `Project`)
